# FoodBook

Локальное Django-приложение каталога любимых блюд. В этой версии намеренно оставлены две неисправленные проблемы безопасности для проверки на собственном компьютере и на фиктивных аккаунтах:

1. **IDOR / Broken Access Control** — авторизованный пользователь может открыть запись другого пользователя по её числовому ID.
2. **Reflected XSS** — поисковая строка вставляется в HTML без экранирования.

Уязвимые демонстрационные маршруты доступны только при `DEBUG=True` и обращении с loopback-адреса. Не публикуйте приложение в интернете и не используйте реальные персональные данные.

## Установка (Windows PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

Откройте `http://127.0.0.1:8000/admin/`. Создайте два обычных тестовых аккаунта и две записи `FoodEntry`, назначив каждой свой `owner`. Для IDOR войдите как первый пользователь и укажите ID записи второго.

## Регистрация и добавление записей

На главной странице доступны ссылки «Войти» и «Регистрация». После создания аккаунта пользователь может войти и выбрать «Добавить запись». Новая запись автоматически связывается с аккаунтом, который её создал. Добавление доступно только вошедшим пользователям.

## Автоматические тесты уязвимой версии

В отдельном терминале из корня проекта:

```powershell
python manage.py test catalog --verbosity=2
```

Тесты должны подтвердить: анонимный пользователь перенаправляется на вход; авторизованный пользователь может прочитать чужую запись через IDOR; свою запись он тоже может прочитать; поисковый параметр отражается как HTML без экранирования.

## Скрипты проверки

Скрипты работают только с локальным адресом приложения.

```powershell
python security_scripts/check_idor.py --username alex_test --password "ВАШ_ПАРОЛЬ" --entry-id 2
python security_scripts/check_xss.py
```

Для `check_idor.py` используйте ID записи второго тестового пользователя. Скрипт выполняет вход в приложение и проверяет, доступна ли запись по ID. XSS-скрипт отправляет безвредный демонстрационный маркер и проверяет, что сервер вернул его без экранирования.

## Исправления

Сайт в этом архиве намеренно оставлен уязвимым. Исправленный вариант представлен только в виде diff-файлов в `patches/`:

- `fix_idor.diff` — добавляет проверку владельца при получении записи;
- `fix_xss.diff` — удаляет небезопасный фильтр `safe`, возвращая автоэкранирование Django;
- `tests_after_patch.py` — тесты для проверки исправленного поведения.

Применять исправления из корня проекта:

```powershell
git apply patches/fix_idor.diff
git apply patches/fix_xss.diff
Copy-Item patches/tests_after_patch.py catalog/tests.py
python manage.py test catalog --verbosity=2
```

Используйте только локально, с фиктивными аккаунтами и данными.
